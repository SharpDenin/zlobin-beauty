# Роли и права

Источник: identity-роли, membership организации, формат занятости мастера (`work_type`), проверки сервисов. UI-фильтр `cabinet.can()` совпадает с навигацией, но **не заменяет** backend.

Публичная регистрация выдаёт только `client`, `master`, `supplier`. Администратор салона и представитель появляются через приглашение / команду, не через самоназначение в production.

## Сводка

| Роль | Что видит | Что может делать |
| --- | --- | --- |
| Владелец салона | Старт салона, расписание организации, записи, команда, салон, аналитика | Управлять салоном и филиалами, QR и сотрудниками, смотреть календарь салона, настройки |
| Администратор салона | Операции салона, команда, выдача заказов | Почти то же по команде и выдаче; не владелец, без полной аналитики владельца |
| Мастер салона | Свои записи, календарь, портфолио, клиенты | Вести график и услуги, принимать запись, писать в мессенджере |
| Частный мастер | Свой профиль и календарь без обязательного салона | Публичный профиль, запись, портфолио, косметика, база знаний |
| Арендатор / выездной | Своё расписание, точка работы | Работа в чужом салоне или на выезде. Аренда кресла **в своём** салоне запрещена (`chair_own_salon_lease`) |
| Клиент | Поиск, карточка мастера, свои записи, магазин | Записаться, отменить свою запись, писать мастеру, заказать в магазине |
| Поставщик | Свой контур: товары, склад, знания, заказы | Публиковать каталог и статьи, проводить заказы |
| Представитель | Склад и полевые задачи поставщика | Маршруты и склад, без полного кабинета поставщика |
| Администратор платформы | `/admin` | Справочники, пользователи, модерация контента |

Подписи в интерфейсе (`cabinetLabel`): «Владелец салона», «Частный мастер», «Мастер салона», «Аренда кресла», «Выездной мастер» — слова «Кабинет» нет.

## По областям

### Календарь

- Свой календарь: мастер (любой формат занятости, кроме чистого клиента/поставщика). Представитель видит календарь в смысле UI-флага `calendar`, но не календарь чужого салона.
- Календарь организации: только owner/admin **этой** организации. Чужой `organization_id` → 403.
- Клиент и поставщик не читают `/v1/calendar/appointments` чужого салона.

### Запись

- Клиент создаёт запись к опубликованному мастеру (с учётом чёрного списка и блокировки аккаунта).
- Мастер/салон видят записи, где они сторона.
- Чужой id записи: 403/404. Отмена и перенос — только участник или салон с правом.

### Портфолио

- Публичный просмотр на странице мастера.
- Создание / правка / удаление — владелец профиля (`/v1/me/master/portfolio/...`). Чужой элемент — 403/404.

### Контакты и сообщения

- Контакт принадлежит пользователю. Удалить чужой контакт нельзя.
- Сообщение видят участники беседы. Вложение `message` — через проверку communications.

### Салон и мастер

- PATCH организации — owner/admin этой орг.
- Профиль мастера `/v1/me/master` — сам мастер.
- Типы профессий: справочник общий; привязку меняет сам мастер (с блокировкой уже использованных в услугах).

### Поставщик, заказы, склад

- Заказ поставщику: доступ у покупающей организации **или** организации-поставщика.
- Клиент и чужой мастер чужой заказ не читают (403/404).
- Каталог опубликованных товаров — витрина для мастеров.

### База знаний

- Список опубликованных статей — мастерам/поставщикам.
- Черновик и правка: автор или owner/admin орг-поставщика. Иначе 403/404 (для чужого черновика — как «не найдено»).

### QR и приглашения

- Создать / список / отозвать: owner/admin салона.
- Посмотреть приглашение по токену — публично (имя салона и роль, без лишних данных).
- Принять — авторизованный пользователь. Токен хеширован, TTL, лимит использований, revoke.

### Аренда кресла

- Мастер может арендовать кресло в **чужом** салоне.
- Сотрудник этого салона — отказ с кодом `chair_own_salon_lease`.

### Медиа

- Загрузка: любой авторизованный, с лимитом и purpose.
- Удаление: только `owner_user_id`.
- Чтение витринных purpose — публично по задумке.

## Frontend hide

Пункт «Команда» не показывается клиенту. Это UX. Проверка — `GET/POST /v1/organizations/{id}/invites` на backend.
